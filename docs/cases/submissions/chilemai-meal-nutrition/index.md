# 用 WorkBuddy 核对麦当劳套餐组成与整餐营养

本文整理自2026年10月15日已完成的真实只读查询，文字由AI辅助整理。未在本文整理时重新查询价格，也未进行订单或支付测试。

## 场景描述

用户希望在杭州西湖附近到店自取，菜单预算40元、整餐不超过500千卡。难点是门店菜单与营养表的名称、规格不一定一致；套餐名称也不能直接对应同名汉堡的单品热量。

## 想要完成的任务

确认公开门店与当次在售菜单，给出两个能说明组成、价格口径和营养来源的方案。无法核实的营养数据应保留为未知。

## 使用的 Skill

| Skill | 用途 | 来源或安装方式 |
| --- | --- | --- |
| 吃了麦（chilemai） | 组织门店查询、菜单匹配、套餐组成核实及整餐建议 | [源码与安装说明](https://github.com/HessianZ/chilemai)、[SkillHub条目](https://skillhub.cn/skills/indiv-hessian/chilemai) |

Skill依赖麦当劳MCP；仓库的Python辅助脚本使用标准库做离线数据对齐和组合计算，脚本本身不是MCP工具。

## 前置条件

- 环境：Windows桌面WorkBuddy。原查询记录没有保存客户端版本号，不将后续观察到的版本回填为当时版本。
- 按[麦当劳MCP官方说明](https://github.com/M-China/mcd-mcp-server)自行取得Token并配置连接；Token只放在本机配置中，不发给作者或评论区。
- 按项目安装说明安装Skill；如果运行离线辅助脚本，需要Python。
- 本例只用公开地点关键词，不需要私人地址簿、订单或支付权限。
- 不熟悉配置的读者可先看[免Token历史案例页](https://hessianz.github.io/chilemai/)，它只展示两份固定记录，不连接MCP。

## 在 WorkBuddy 中的操作

1. 确认麦当劳MCP查询工具已连接，再输入下面的只读任务。若连接失败，先解决配置问题，不用模型记忆中的菜单代替工具结果。
2. 先查询门店，确认营业状态与取餐方式。本次历史记录选中杭州灵隐景区餐厅，公开门店编号3330257。
3. 查询该门店菜单及官方营养数据，区分菜单价格与最终实付。名称或规格不能精确对齐时，不直接给确定营养结论。
4. 对候选套餐额外查询详情，核实默认选项，再逐项加总营养；改选饮料或其他组成后重新计算。
5. 输出两个方案并列出未验证项。不要继续调用下单或支付操作。


## 在 WorkBuddy 中的效果

原记录实际完成四类查询：`query-nearby-stores`、`list-nutrition-foods`、`query-meals`、`query-meal-detail`，时间约为2026年10月15日11:58—12:04。返回5家公开门店、演示门店84项菜单、160行营养文本；营养文本不是JSON。

菜单与营养对齐结果为20项精确对齐、22项待确认、42项未对齐。未对齐项没有自动纳入严格营养合计。

| 历史方案 | 当时菜单估价 | 整餐千卡 | 蛋白质 |
| --- | ---: | ---: | ---: |
| 板烧鸡腿堡＋纯悦 | 27＋9＝36元 | 391＋0＝391 | 23克 |
| 酥脆无双套餐（当时默认组成） | 31元 | 328＋106＋0＝434 | 23克 |

第二个方案经详情确认是脆汁鸡琵琶腿、迷你薯条、无糖可口可乐中杯。434千卡是三项相加，不是把单品热量当作套餐热量。

## 验收标准

- 先看到成功的真实工具返回，再生成建议；记录日期、门店和取餐方式。
- 菜单价格单位核实后再计算；不能把历史菜单估价承诺为当前实付。
- 套餐默认组成来自详情；逐项营养能对齐，计算和434千卡示例一致。
- 缺少规格或营养数据时标未知；不为凑满两份方案编造数据。
- 本次无私人地址读取、订单创建或支付记录。新的试用应重新检查自己的调用记录。

## 遇到的问题

该门店当时没有无糖可乐单点，虽然套餐选项中有无糖可乐。单品组合因此使用当时在售的纯悦，不能从套餐选项反推单品也可购买。

官方营养表覆盖不足，不能为84项菜单都计算确定营养。套餐名字、规格或选项变化也会影响结果。

## 安全与限制

当次没有调用`calculate-price`，没有验证优惠、打包费或最终实付；上述价格仅是历史菜单估价。当前供应、价格和默认搭配需重新查询。项目非麦当劳官方产品，营养数据只供搭配参考。

Skill具备组织更多点餐流程的设计，本例只验证查询。切勿把“只读提示词”当作权限隔离保证，仍应检查工具调用并拒绝意外的写操作。不要公开Token、手机号、私人地址或支付链接。

## 可以怎样复用

把地点、预算和营养目标替换为自己的条件，但重新取当次数据。保留“门店菜单→名称与规格对齐→套餐组成→逐项营养→价格口径”的检查顺序；不把这两份历史方案直接套到其他门店。
